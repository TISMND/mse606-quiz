# Glossary and "Terms You Struggle With" Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** a glossary of about 300 checked terms, a "Terms You Struggle With" screen built from
each student's misses, and a "View key terms" reveal after wrong answers, all shipped without
disturbing students already using the live site.

**Architecture:**
- Pure term logic goes in `js/terms.js`, tested with `node --test`.
- Rendering goes in `js/terms-ui.js`.
- Existing files get thin hooks only. `app.js` loads `glossary.json` and `terms-ui.js` with a
  dynamic `import()` inside `try`, so a failure leaves `ctx.glossary = null` and every hook renders
  nothing.
- Content:
  - agents write `work/glossary/chNN.json`, and checkers write `work/glossary-checked/chNN.json`;
  - `tools/build-glossary.mjs` produces `glossary.json`;
  - taggers add `terms` to questions in `work/tagged/chNN.json`;
  - `tools/build-questions.mjs` prefers `work/tagged/` over `work/checked/`.

**Tech Stack:** as before: plain ES modules, Node 24 `node:test`, no dependencies.

**Spec:** `docs/superpowers/specs/2026-11-12-glossary-design.md`. The base spec is
`docs/superpowers/specs/2026-11-12-mse606-study-quiz-design.md`.

## Global Constraints

- **Live users:**
  - No change to the `users/{uid}` shape, the `mse606.*` localStorage keys, question ids or any
    existing field.
  - New code goes in new files.
  - Existing files get only hooks that tolerate `ctx.glossary == null` and questions without
    `terms`.
- **Copy:** "Terms You Struggle With", "Glossary", "Struggling (N)", "All terms (M)", "Missed K×",
  "Don't confuse with", "Exam trap", "Drill the K questions you missed →", "View key terms · N ▾",
  "Key terms", "No struggling terms. Nice.", "Search terms…".
- **Term card:** the term in `var(--good)` bold, the chapter in mono on the right, and `short`
  below. When open, the border is `rgba(47,217,138,.6)`, there's a dashed divider, the
  confused-with names are amber and the trap has a red left rule (mockup `glossary-v1.html` #3).
- **Menu caption:** "N terms from your misses · full glossary inside" when N > 0, otherwise
  "Glossary · M terms".
- **Term ids:** match `/^[a-z0-9]+(-[a-z0-9]+)*$/`, are unique, and are permanent.

## Review Focus

1. **Stale cache** (new `app.js` with an old `questions.json` that has no `terms`, or a missing
   `glossary.json`): the app works exactly as before and the glossary UI is hidden. Covered by
   Task 1 (`termsFor` on a question without `terms`) and verified in Task 4 by blocking
   `glossary.json`.
2. **Miss ids or term tags that no longer exist:** they are ignored in Struggling counts and in
   key-term lists. Covered by Task 1 tests.
3. **A question tagged with a term from another chapter:** it resolves and shows that term's own
   chapter. Covered by a Task 1 test.
4. **Search with odd input** (empty, upper case, regex characters such as `(`): it does not throw;
   empty returns everything. Covered by a Task 1 test.
5. **"Drill the K questions"** where some of those questions are now skipped: skipped ones are
   excluded, and the button hides when K = 0. Covered by a Task 1 test (`struggling` excludes
   skipped).

### Task 1: Term logic

**Files:**
- Create: `js/terms.js`
- Test: `tests/terms.test.mjs`

**Interfaces (Produces):**
- `indexGlossary(glossary) -> { terms: Term[], byId: Record<id, Term> }`
- `termsFor(q, byId) -> Term[]`: `q.terms` resolved in order. Unknown ids are dropped, and a
  missing `q.terms` gives `[]`.
- `struggling(bank, user, byId) -> [{ term, count, qids }]`
  - Built from the questions whose id is in `user.misses`, excluding skipped questions and ids
    not in the bank.
  - Each tagged term gets its count of such questions and their ids.
  - Sorted by count descending, then chapter, then term (case-insensitive).
- `sortTerms(terms) -> Term[]`: by chapter, then term, case-insensitive.
- `searchTerms(terms, query) -> Term[]`: case-insensitive substring match on `term` and `short`,
  with no regex involved. A blank query returns the list unchanged.

- [ ] **Step 1: Write the failing tests.** Fixtures: a glossary of 4 terms in chapters 7 and 5,
  and a bank of 4 questions with `terms`, where one is tagged with a ch-5 term and has an unknown
  tag, and one has no `terms`.
  - `termsFor` drops the unknown id, and a question with no `terms` gives `[]`.
  - `struggling`:
    - counts a term once per missed question;
    - ignores a miss id that isn't in the bank, and skipped questions;
    - sorts by count, then chapter;
    - returns `qids`.
  - `searchTerms` matches "ENRICH" and "vertical" (from `short`); `"("` returns `[]` without
    throwing; `""` returns everything.
  - `sortTerms` puts chapter 5 before chapter 7.
- [ ] **Step 2: Run them.** `npm test` should FAIL because the module is missing.
- [ ] **Step 3: Implement `js/terms.js`.**
- [ ] **Step 4: Run them.** `npm test` should PASS.
- [ ] **Step 5: Commit** with `feat: term logic`.

### Task 2: Glossary build and question tags validation

**Files:**
- Create: `tools/build-glossary.mjs`, `tests/glossary.test.mjs`
- Modify: `tools/validate.mjs`, `tools/build-questions.mjs`

**Interfaces (Produces):**
- `validateTerm(t) -> string[]`, which checks:
  - the id slug format;
  - the chapter is in `CHAPTERS`;
  - `term` and `short` are non-empty;
  - `short` is at most 220 characters;
  - `confusedWith` is an array of `{ id, note }` if present.
- `glossary.json` = `{ version, terms: Term[] }`.
  - Merged from `work/glossary-checked/chNN.json`, falling back to `work/glossary/` with a
    warning.
  - A duplicate id keeps the first entry, which comes from the lower chapter. The build prints a
    `COLLISION id chA/chB` line for review.
  - `confusedWith` references to unknown ids are removed, with a warning.
- `build-questions.mjs`:
  - reads `work/tagged/chNN.json` first, then `work/checked/`;
  - when `glossary.json` exists, **exits 1** if any question tag isn't in it;
  - always leaves out an empty `terms`.

  - `validateTerm` flags a bad slug (`Job_Enrichment`), chapter 4, an empty `short`, and a
    `short` of 300 characters.
  - A valid fixture returns `[]`.
  - When `glossary.json` exists: every term validates, ids are unique, and every
    `confusedWith.id` exists.
  - When `questions.json` and `glossary.json` both exist: every `q.terms` id exists in the
    glossary.
- [ ] **Step 2: Run them.** `npm test` should FAIL because `validateTerm` isn't exported.
- [ ] **Step 3: Implement** both scripts.

### Task 4: UI

**Files:**
- Create: `js/terms-ui.js`
- Modify, hooks only:
  - `js/app.js`: load the glossary;
  - `js/menu.js`: the Modes button;
  - `js/quiz.js`: after a wrong submit, and inside the summary review;
  - `styles.css`: append the term styles.

**Interfaces:**
- Consumes: Task 1's functions, and `runQuiz(ctx, questions, 'drill')`.
- Produces:
  - `termCardHTML(term, { count, qids })`: a closed card with `data-term`.
  - `keyTermsHTML(q, ctx)`: the button plus a hidden container, or `''` if there's no glossary
    or no terms.
  - `bindTerms(root, ctx)`: delegated clicks for opening and closing cards, revealing key terms,
    and the drill button.
  - `renderGlossary(ctx)`: the full screen.
- `app.js`:
  - after `questions.json` loads, `try { ctx.glossary = indexGlossary(await (await fetch('glossary.json')).json()); ctx.termsUI = await import('./terms-ui.js'); } catch { ctx.glossary = null; }`;
  - `ctx.go('glossary')` calls `ctx.termsUI.renderGlossary(ctx)`.

**Behaviour** (per the spec):
- The glossary opens on Struggling if N > 0, otherwise on All terms.
- Search applies to the active tab.
- Tapping a card toggles it in place.
- The drill button starts `runQuiz` with the `qids` that exist in the bank and aren't skipped.
- "← Menu" returns to the menu.
